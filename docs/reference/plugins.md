# Plugin authoring

Farmall loads plugin modules listed in the top-level `plugins` array. A module can default-export one plugin or an array, or export an array named `plugins`. Relative specifiers and bare packages resolve from the config root with Node import conditions. Modules are freshly loaded so watch-mode and repeated runs do not retain stale exports.

Plugin IDs must be unique across built-ins and loaded modules. Every plugin has `apiVersion: 1`, an `id`, a stage `kind`, an optional synchronous `validate` function, and an asynchronous `run` function.

## Exported types and helpers

The implementation exports these contracts from `@farmall/core`:

```ts
import {
  err,
  ok,
  stage,
  type Artifact,
  type CoreError,
  type DesiredFile,
  type Diagnostic,
  type DirectOutput,
  type Emission,
  type FileContent,
  type FileRecord,
  type JsonObject,
  type JsonValue,
  type LintPlugin,
  type OutputPlugin,
  type PluginContext,
  type PosixMode,
  type Result,
  type SourcePlugin,
  type StageResult,
  type TransformPlugin,
} from "@farmall/core";
```

`Result<T, E>` is `{ ok: true, value: T } | { ok: false, error: E }`. Use `ok(value)` and `err(error)` to construct it. Source, transform, and output plugins wrap their successful value and stage diagnostics with `stage(value, diagnostics?)`.

`PluginContext` exposes the config root plus contained file helpers. `read(path)` remains the text-compatible UTF-8 API. Use `readBytes(path)` for exact bytes or `readFileRecord(path)` to read exact bytes and the permission mode together without a redundant file read. Sorted `glob(patterns)` and recursive `walk(path)` return canonical root-relative file paths. All helpers return `Result` values. Globs support brace and globstar patterns, exclude `.git` and `node_modules`, and reject absolute patterns, parent-traversal segments, and matches that escape through symlinks. Walks include hidden files. Reads and walks enforce the same root-containment contract.

`FileContent` is `string | Uint8Array`. Artifact primary `content` remains a string, while `ArtifactFile.content`, `DirectOutput` files, and `DesiredFile.content` accept either representation. File records may carry an optional integer POSIX `mode` from `0` through `0o7777`.

Artifact `metadata` is a `JsonObject`, recursively composed from strings, finite numbers, booleans, null, arrays, and objects. External plugins cannot return bigint, undefined, functions, symbols, cyclic references, accessors, sparse arrays, typed arrays, class instances, or other non-JSON values in metadata.

## Source example

A source can emit normalized `Artifact` values, native `DirectOutput` values, or both:

```ts
import { ok, stage, type Artifact, type DirectOutput, type SourcePlugin } from "@farmall/core";

const source = {
  apiVersion: 1,
  id: "acme:source",
  kind: "source",
  run: async (_options, context) => {
    const instructions = await context.read("shared/AGENTS.md");
    if (!instructions.ok) return instructions;

    const artifact: Artifact = {
      type: "artifact",
      id: "instructions:shared/AGENTS.md",
      kind: "instructions",
      name: "AGENTS",
      source: "shared/AGENTS.md",
      content: instructions.value,
      metadata: {},
      files: [{ path: "AGENTS.md", content: instructions.value }],
    };

    const nativeFile = await context.readFileRecord("shared/tool");
    if (!nativeFile.ok) return nativeFile;

    const native: DirectOutput = {
      type: "output",
      id: "output:codex-config",
      output: "codex",
      source: "generated by acme:source",
      files: [{ path: "bin/tool", ...nativeFile.value }],
    };

    return ok(stage([artifact, native]));
  },
} satisfies SourcePlugin;

export default source;
```

## Stage contracts

```ts
interface SourcePlugin {
  run(options, context): Promise<Result<StageResult<readonly Emission[]>, CoreError>>;
}

interface TransformPlugin {
  run(emissions, options, context): Promise<Result<StageResult<readonly Emission[]>, CoreError>>;
}

interface LintPlugin {
  run(emissions, options, context): Promise<Result<readonly Diagnostic[], CoreError>>;
}

interface OutputPlugin {
  run(emissions, options, context): Promise<Result<StageResult<readonly DesiredFile[]>, CoreError>>;
}
```

An output plugin returns `DesiredFile` records with `path`, `content`, optional `mode`, `output`, `plugin`, `sources`, and `writePolicy`. It must not write to disk. The core normalizes claims, checks containment and ownership, verifies stale plans, writes atomically, and rolls back failed applies.

Plugin exceptions are converted to `CoreError` values at the pipeline boundary, but plugins should return expected failures through `err`. Farmall validates every external `Result`, `StageResult`, artifact, direct output, diagnostic, and desired file before sorting or planning. `Uint8Array` content and modes from `0` through `0o7777` are accepted. Invalid paths, modes, write policies, strings, or metadata become plugin errors instead of escaping into planner failures.

Options and upstream emissions passed to transforms, lint plugins, and outputs are isolated for each invocation. Objects and arrays are cloned and frozen. Typed arrays are copied rather than frozen because JavaScript cannot freeze their indexed elements; a plugin can mutate its private byte copy without corrupting upstream state, but should still return replacement values. This isolates sibling outputs and lint stages from each other and from transformed pipeline state.

The context itself is frozen before invocation, and every validated plugin result is cloned before its surrounding objects and arrays are frozen. A plugin therefore cannot replace context methods for a sibling or retain a reference that mutates an already accepted result. Context methods remain callable normally.
